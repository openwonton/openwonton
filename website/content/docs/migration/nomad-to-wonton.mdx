# Migration: OpenWonton to OpenWonton

OpenWonton is a fork of HashiCorp Nomad with a focus on a smooth migration path for existing users. This guide outlines what changed, what stayed compatible, and the small set of updates you may want to make.

## Quick Checklist

1. Install OpenWonton and confirm `wonton version` works.
2. Keep using the `nomad` shim for compatibility, or update scripts to call `wonton`.
3. If you import the Go API, update module paths to `github.com/openwonton/openwonton/api`.

## Key Changes

*   **CLI Binary:** The primary CLI binary is now `wonton`.
*   **Project Name:** The project is now known as OpenWonton.
*   **Go Module Path:** Go consumers should use `github.com/openwonton/openwonton` (API: `github.com/openwonton/openwonton/api`).

## Compatibility

OpenWonton maintains a high degree of compatibility with OpenWonton. Job files, APIs, and the overall architecture remain the same unless otherwise noted. We aim to keep OpenWonton defaults and behaviors intact so existing clusters can migrate with minimal change.

## Migrating to `wonton`

The most significant change you'll encounter is the renaming of the CLI binary.

### For Users

If you are used to running `nomad` commands, you can create a simple shell alias to make the transition seamless:

```bash
alias nomad="wonton"
```

We also ship a `nomad` shim (or symlink in some packages) that invokes `wonton` so existing scripts and automation continue to work without modification.

### For Scripts and Automation

For your scripts and automation, we recommend updating them to use `wonton` directly. This will ensure that your scripts continue to work even if the `nomad` shim is removed in a future release.

A simple `sed` command can help you replace most occurrences in your scripts:

```bash
sed -i 's/nomad/wonton/g' your-script.sh
```

**Note:** Always review the changes before applying them, as this command might replace unintended occurrences of the word "nomad".

## Configuration and Data

Your existing OpenWonton configuration files and data directory can be used with OpenWonton without any changes. The API surface is designed to remain compatible, so existing clients should continue to work.

## Environment Variables

OpenWonton-compatible environment variables (such as `NOMAD_ADDR`, `NOMAD_TOKEN`, and `NOMAD_NAMESPACE`) remain supported to preserve compatibility with existing tooling.

## Go API Clients

If you use the Go API client, update import paths from OpenWonton to OpenWonton:

```go
import "github.com/openwonton/openwonton/api"
```

Your code should otherwise remain compatible.

## Future Changes

We will document any future breaking changes in our release notes. We are committed to maintaining a stable and reliable platform.
